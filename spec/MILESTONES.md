# MILESTONES - משחק סיימון

תוכנית הפיתוח מבוססת על [PRD.md](./PRD.md), [ARCHITECTURE.md](./ARCHITECTURE.md) ו-[DESIGN.md](./DESIGN.md). ההתנהגות נקבעת ב-PRD, המימוש הטכני ב-ARCHITECTURE, והמראה ב-DESIGN וב-[Mockups המתוקנים](./mockups.png), לרבות לוח המשחק העגול.

המסמך מגדיר עבודה עתידית ואינו מעיד שאבני הדרך כבר מומשו. כל Milestone תלוי בהשלמת קודמו ובאישור המשתמש לעבור אליו.

## Development Execution Rules - כללי ביצוע הפיתוח

1. **יש לפתח את ה-Milestones לפי הסדר המוגדר במסמך.** אין להתחיל עבודה על Milestone מאוחר יותר במקביל.
2. **לאחר השלמת כל Milestone יש לעצור את הפיתוח** ולהציג למשתמש את התוצר העובד, דרך פשוטה לבדוק אותו ותוצאות בדיקה מול כל סעיף ב-Definition of Done.
3. **אין להתחיל בפיתוח ה-Milestone הבא ללא אישור מפורש של המשתמש.** שתיקה או הצלחת בדיקות אינן אישור.
4. בדוח הסיום יש להפריד בין בדיקות שבוצעו ועברו, בדיקות שנכשלו ובדיקות שלא ניתן היה לבצע. תנאי שלא נבדק אינו נחשב כמתקיים. אם נדרשת בדיקה במכשיר שאין ל-AI גישה אליו, יש לבקש מהמשתמש לבצע אותה עם הוראות קצרות ולתעד את התוצאה.
5. יש לתקן כשלים במסגרת אבן הדרך הנוכחית לפני הכרזה על השלמתה. אישור להתקדם אינו תחליף להצגת פערים ידועים.
6. כל תוצר יוצג עם היכולות הזמינות בו והיכולות שנותרו לאבני הדרך הבאות. אין להציג נתוני דוגמה כתוצאות אמיתיות או רכיב שאינו ממומש כיכולת עובדת.
7. יש לשמור על היקף המוצר: Frontend בלבד ושני מסכים. אין להוסיף Backend, Database, חשבונות, Analytics או שירות AI. אין Supabase או Database Migrations בתוכנית זו.
8. פרטים שנותרו פתוחים במקורות, כגון קצב ההארה, נוסחי הודעות ומיקום מצבי הסיום, יושלמו באופן מינימלי במסגרת אבן הדרך הרלוונטית, יסומנו כהחלטות מימוש חדשות ויוצגו בבדיקת התוצר. אין להציגם כעיצוב שכבר אושר או לשנות באמצעותם את דרישות המוצר.

| 2. משחק מלא ותוצאה אחרונה     | משחק עם אורות וצלילים, סיום, משחק חוזר ושמירת תוצאה            |

## Milestone 1 - בסיס עובד ושני מסכים ✅

**מטרה:** להקים את סביבת העבודה ולספק תוצר שניתן לפתוח ולנווט בו, בעיצוב המוצר.

### מה יש לממש

- פרויקט Vite ו-TypeScript ללא UI Framework, עם CSS רגיל, Node.js ו-npm בהתאם ל-ARCHITECTURE. נעילת תלויות ב-Lockfile והגדרת Type checking, Build, Vitest ו-Playwright.
- Git Repository ייעודי ב-GitHub עם ענפי עבודה ו-CI לבדיקות ול-Build; ללא פריסת האתר בשלב זה. יש לברר את חשיפת ה-Repository עם המשתמש אם טרם הוגדרה, משום שמאגר ציבורי הוא הנחת העלות ב-ARCHITECTURE ולא החלטה עסקית מאושרת.
- מסכי בית ואודות באותו עמוד, עם ניווט פנימי וללא Reload.
- מימוש השפה העיצובית: עברית ו-RTL, Heebo מקומי עם Fallback, צבעים, כפתורים וכרטיסים בהתאם ל-DESIGN.
- לוח משחק עגול בארבעה מקטעים קמורים, במיקומי הצבעים הנכונים. בשלב זה הלוח מוצג במצב Rest; הפעלת המשחק טרם זמינה ולחצן ״התחל״ אינו פעיל בגרסת הביניים.
- תיאור והוראות באודות, כרטיס במצב ללא תוצאה וכפתור ״חזרה למשחק״. אין להציב בכרטיס את תוצאת הדוגמה 7 מתוך 10.

### תוצר מצופה

אתר מקומי שנפתח וניתן לעבור בו בין שני מסכים מעוצבים, עם קוד מנוהל ב-GitHub ובדיקות בסיס פעילות. המשחק עצמו יתווסף ב-Milestone 2.

### Definition of Done

- [ ] התקנה נקייה באמצעות `npm ci`, בדיקת TypeScript ו-Build מסתיימות בהצלחה.
- [ ] מעבר בית → אודות → בית עובד ללא טעינה מחדש; רענון מציג בית במצב המתנה.
- [ ] בדיקת Playwright מאמתת ניווט ותוכן מרכזי. ה-CI מריץ אותה ואת בדיקות הפרויקט הקיימות בהצלחה.
- [ ] שני המסכים נבדקו חזותית ברוחבי מובייל מול ה-Mockups: הלוח עגול ביחס 1:1, מיקומי הצבעים נכונים, ואין גלילה אופקית או חיתוך טקסט. תוכן ארוך נגיש בגלילה אנכית.
- [ ] העברית, כיווניות המספרים, גדלי המגע ומצבי Focus תואמים למסמכים; תוכן המסך המוסתר אינו מקבל Focus.
- [ ] אין בקשות לפונטים או לספריות UI מ-CDN חיצוני, אין נתוני תוצאה מזויפים ואין פריסה ציבורית של האתר בשלב זה.

## Milestone 2 - משחק מלא ותוצאה אחרונה ✅

**מטרה:** לאפשר משחק שלם מתחילתו ועד לתוצאה, משחק חוזר וצפייה בתוצאה שנשמרה.

### מה יש לממש

- Game Engine, Controller, Sequence Player ו-Audio Adapter לפי חלוקת האחריות ב-ARCHITECTURE, מחוברים למסך הבית.
- התחלה באמצעות ״התחל״, רצף אקראי מצטבר, ארבעה צלילים מובחנים, מצבי Rest ו-Lit וקלט מגע.
- התקדמות עד 10 שלבים, סיום בטעות הראשונה, הודעת הפסד או ניצחון, ניקוד ולחצן ״שחקו שוב״ בתוך מסך הבית.
- הבחנה בין הצגת הרצף לתור המשתמש. בחירת קבועי תזמון קבועים לכל השלבים ותיעודם כהחלטת מימוש לבדיקה.
- שמירת תוצאת המשחק האחרון ב-Local Storage לפי ה-Schema המוגדר, והצגתה באודות.
- טיפול בתוצאה חסרה או פגומה, כשל כתיבה וכשל שמע בהתאם להנחות המתועדות. בכשל שמירה אין להציג תוצאה ישנה כתוצאה החדשה.
- מניעת קלט בזמן הצגת הרצף ולאחר סיום, מניעת קלט כפול וביטול Callbacks ממשחק קודם. מעבר לאודות במהלך משחק יתמוך כבר בהשהיה הבסיסית הנדרשת ב-PRD; Milestone 3 ישלים את בדיקות המעברים והטיפול במחזור חיי המכשיר.

### תוצר מצופה

משחק מקומי מלא עם אורות וצלילים, מסכי סיום בתוך הבית, אפשרות לשחק שוב ותוצאה אחרונה שנשמרת לאחר פתיחה מחדש.

### Definition of Done

- [ ] אפשר להשלים משחק ולשחק שוב דרך ה-UI. כל ארבעת הצלילים נשמעים בעקבות פעולת התחלה; צבע שמופיע פעמיים ברצף מוצג כשתי הארות נפרדות.
- [ ] בדיקות Vitest עם אקראיות נשלטת מאמתות הוספת צבע אחד לרצף הקודם, אפשרות לחזרות וסיום לאחר שלב 10 ללא שלב 11.
- [ ] מאומתים הפסד בשלב 1 עם ניקוד 0, הפסד בשלב 10 עם ניקוד 9 וניצחון עם ניקוד 10. הניקוד גדל רק לאחר השלמת שלב.
- [ ] קלט בזמן Playback או אחרי סיום אינו משנה תוצאה; מחוות מגע אחת אינה נרשמת פעמיים. קלט מקביל מטופל לפי ה-ARCHITECTURE.
- [ ] תוצאה נמוכה מחליפה קודמת. התחלה חדשה ורענון באמצע משחק אינם דורסים אותה. אחרי רענון המשחק מתאפס והתוצאה נשארת באודות.
- [ ] נתון פגום, Storage חסום וכשל שמע נבדקו באופן מבוקר: אין קריסה, ותגובת הממשק תואמת למסמכים.
- [ ] Playwright מאמת משחק עד סיום, משחק חוזר, מעבר לאודות ושחזור התוצאה לאחר Reload.
- [ ] מצבי התור והסיום נבדקו חזותית במובייל. ההודעות בעברית, אין מסך נוסף, וההחלטות העיצוביות שלא הופיעו ב-Mockups מוצגות למשתמש.
- [ ] בדיקות, Type checking ו-Build עוברים ב-CI.

## Milestone 3 - יציאה וחזרה בטוחה למשחק ✅

**מטרה:** לשמור על רצף שימוש תקין כשהמשתמש קורא הוראות, עובר לאפליקציה אחרת או נועל את המכשיר.

### מה יש לממש

- השלמת השהיה וחזרה בכל נקודה: באמצע הצגת הרצף, באמצע תשובה ובין שלבים.
- ביטול Timers, שמע ופעולות אסינכרוניות ממתינות; שימוש ב-`runToken` למניעת עדכונים ישנים.
- טיפול ב-Page Visibility, ב-`pagehide` וב-BFCache לפי ה-ARCHITECTURE.
- חידוש AudioContext בעת חזרת משתמש כשאפשר, וטיפול בחסימת שמע לפי ההנחה הקיימת, ללא מסך או פקד חדש.

### תוצר מצופה

משחק שאפשר לצאת ממנו לאודות או לרקע ולחזור אליו בלי לאבד שלבים שהושלמו, בלי לקבל צבע נוסף ובלי לשמוע רצפים חופפים.

### Definition of Done

- [ ] מעבר לאודות באמצע Playback ובאמצע קלט עוצר הארה ושמע. בחזרה מוצג אותו רצף מתחילתו, התשובה החלקית נמחקת והניקוד נשמר.
- [ ] מעבר לפני משחק או לאחר סיומו אינו מתחיל משחק חדש ואינו משחזר משחק שכבר הסתיים.
- [ ] מעבר לרקע וחזרה כשהבית גלוי מפעילים מחדש את השלב; חזרה כשהאודות גלוי משאירה את המשחק מושהה.
- [ ] מעברים מהירים וחוזרים אינם מכפילים רצפים, מאזינים או ניקוד. Callbacks מבוטלים אינם משנים State.
- [ ] שחזור מ-BFCache אינו מפעיל Timers ישנים; Reload מלא מאפס משחק ואינו מוחק תוצאה שמורה.
- [ ] מצב AudioContext חסום נבדק: מתקבל משוב חזותי והודעה בעברית, ואין חסימת משחק או אובדן התקדמות.
- [ ] בדיקות אוטומטיות מכסות את מעברי המצב וביטול הפעולות, וכל בדיקות המשחק הקיימות ממשיכות לעבור. נעשתה בדיקת מעבר לרקע בדפדפן; בדיקות נעילה ושמע במכשירים אמיתיים הן תנאי השלמה של Milestone 5.

## Milestone 4 - שימוש Offline ו-PWA ✅

**מטרה:** לאפשר פתיחה ומשחק ללא רשת לאחר הכנה ראשונית, ולשמור על משחק פעיל בעת עדכון גרסה.

### מה יש לממש

- Manifest ואייקונים בהתאם ל-ARCHITECTURE: שם עברי, RTL, מצב Standalone ונתיבי בסיס עקביים.
- Service Worker באמצעות vite-plugin-pwa ו-Workbox באסטרטגיית `generateSW`.
- Precache לכל משאבי ההרצה, לרבות הגופן המקומי והאייקונים. אין תלות רשת לצלילים הנוצרים באמצעות Web Audio.
- מדיניות עדכון ללא Reload כפוי, ללא Dialog חדש וללא הפעלת גרסה חדשה באמצע שימוש. שמירת Local Storage בעת ניקוי Cache של גרסה ישנה.
- Service Worker כבוי בפיתוח רגיל; בדיקות PWA מול Production Build המוגש מקומית ב-Context מתאים.

### תוצר מצופה

Production Build של המשחק, מוכן להתקנה בסביבות תומכות, ששני מסכיו וכל יכולות המשחק שלו עובדים Offline לאחר Precache. אימות ההתקנה בטלפונים יושלם על HTTPS ב-Milestone 5.

### Definition of Done

- [ ] ה-Manifest, האייקונים, `base`, `start_url`, `id` ו-`scope` תקינים גם תחת נתיב Repository; ה-Service Worker אינו שולט מחוץ לנתיב הפרויקט.
- [ ] לאחר טעינה מקוונת והשלמת Precache, ניתוק הרשת ו-Reload מאפשרים משחק מלא עם צלילים, מעבר לאודות, שמירת תוצאה וקריאתה לאחר Reload נוסף.
- [ ] Playwright בודק Offline מול Build אמיתי עם Service Workers מופעלים, לפחות ב-Chromium, ללא Mock שמחליף את ה-Cache.
- [ ] אין בקשת רשת חיצונית הנדרשת להצגת הטקסט, הגופן, הלוח או השמע.
- [ ] נבדקו שתי גרסאות Build: החדשה ממתינה בזמן שהישנה בשימוש, אינה קוטעת משחק ומופעלת לאחר סגירת ה-Clients הישנים. התוצאה נשמרת.
- [ ] נבדקו כשל בהכנת Cache ומחיקת נתוני האתר: לא מוצגת הבטחה שגויה ל-Offline, ומשחק שכבר נטען אינו קורס בגלל כשל Cache. אין הבטחה לפתיחה ראשונה ללא אינטרנט.
- [ ] כל בדיקות המשחק, הניווט, Type checking ו-Build עוברים.

## Milestone 5 - פריסה ובדיקת מובייל אמיתית

**מטרה:** להעמיד גרסה חיה ב-GitHub Pages עם פריסה אוטומטית, ולוודא שהחוויה עובדת בטלפונים וב-PWA מותקן.

### מה יש לממש

- הגדרת GitHub Pages עם Source מסוג GitHub Actions וכתובת קבועה לפי ה-Repository. יש לוודא שהחשיפה והתוכנית בחשבון תואמות להחלטת המשתמש ולהנחות העלות ב-ARCHITECTURE.
- השלמת Workflow: בדיקות ב-Pull Requests ללא פריסה, ופריסה בעקבות Push ל-`main` רק לאחר מעבר הבדיקות. העלאת אותו Artifact שנבדק, באמצעות ה-Actions הרשמיים והרשאות הפריסה המצומצמות שנקבעו.
- סדרת Concurrency לפריסות ותיעוד דרך Rollback באמצעות Revert ופריסה מחדש, לרבות מגבלת העדכון של Clients שכבר מחזיקים Cache.
- בדיקת האתר החי, ההתקנה והשימוש ב-iPhone וב-Android אמיתיים. הגדרות חשבון ובדיקות שאין ל-AI גישה לבצע ייעשו בידי המשתמש בהדרכה קצרה צעד אחר צעד.

### תוצר מצופה

כתובת HTTPS עובדת עם המשחק המלא, התקנת PWA בסביבות תומכות ותהליך עדכון אוטומטי מתוך GitHub.

### Definition of Done

- [ ] כתובת האתר החי נפתחת ללא שגיאות משאבים; שני המסכים, הגופן, Manifest ו-Service Worker נטענים תחת נתיב ה-Repository הנכון.
- [ ] Workflow מסתיים בהצלחה ומפרסם את ה-Artifact שנבדק. נבדק שכשל בבדיקה מונע פריסה וש-Pull Request אינו מפרסם ל-Production.
- [ ] אין צורך בפריסה ידנית בכל עדכון: Push מאושר ל-`main` מפעיל את המנגנון האוטומטי. שינויי קוד עתידיים עדיין כפופים לכללי האישור במסמך.
- [ ] ב-iPhone וב-Android תועדו מערכת ההפעלה והדפדפן שנבדקו, עם תוצאות של משחק, צלילים, חזרה מאודות, מעבר לרקע, נעילה וחזרה.
- [ ] התקנת PWA ופתיחה ממצב Standalone נבדקו במכשירים תומכים. אחרי הכנה מקוונת אומתו פתיחה ומשחק Offline, כולל שמע ותוצאה אחרונה.
