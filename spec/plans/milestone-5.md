## 1. מה נבנה

- **תיקון הבדיקה הנכשלת ב-WebKit ב-CI**, ושמירת עקבות (Trace) של בדיקות כושלות כדי שיהיה אפשר לאבחן כשל עתידי.

- **בדיקת אתר חי אוטומטית** (Playwright, מופעלת ידנית מהמחשב מול הכתובת החיה): טעינה ללא שגיאות, Manifest, Scope של ה-Service Worker, Offline, ועדכון בין שתי גרסאות.

- **הדרכה צעד אחר צעד למשתמש:** הפעלת Pages, ובדיקות ב-iPhone וב-Android.

**ללא שינוי בממשק או בהתנהגות המשחק.** אין מסך, כפתור או הודעה חדשים. אין Domain מותאם, אין Analytics.

## 4. מבנה ה-Workflow

```
on: pull_request, push ל-main
permissions (ברירת מחדל): contents: read

concurrency (כל ה-Workflow): לפי ענף; ריצה חדשה מבטלת קודמת רק ב-Pull Request.
  ב-main לא מבטלים ריצה באמצע, כדי שפריסה לא תיקטע.

job test:
  checkout → setup-node (.nvmrc, cache npm) → npm ci
  → typecheck → Vitest
  → build (SIMON_BUILD_ID = 7 התווים הראשונים של ה-Commit)
  → התקנת Chromium ו-WebKit → Playwright מול אותו dist/ (SIMON_SKIP_BUILD=1)
  → בכשל: העלאת test-results כ-Artifact לאבחון (7 ימים)
  → רק ב-Push ל-main: configure-pages → upload-pages-artifact (path: dist)

job deploy:
  needs: test   ← כשל בבדיקה = אין פריסה
  if: push ל-main בלבד   ← Pull Request לעולם לא מפרסם
  environment: github-pages (עם כתובת האתר)
  permissions: pages: write, id-token: write (רק כאן)
  concurrency: group "pages", cancel-in-progress: false   ← פריסות בתור, לא חופפות
  deploy-pages
```

- **אותו Artifact שנבדק:** ה-Build נעשה פעם אחת, הבדיקות רצות עליו, והוא זה שמועלה. בדיקות העדכון של PWA בונות לתיקיות נפרדות (`dist-a`, `dist-b`) ולא נוגעות ב-`dist/`.
- **נעילת Actions:** כל Action (`checkout`, `setup-node`, `configure-pages`, `upload-pages-artifact`, `upload-artifact`, `deploy-pages`) נעול ל-Commit SHA של הגרסה העדכנית, עם הערת גרסה. ה-SHA ייבדק מול GitHub בזמן הבנייה.
- **אין Token אישי ואין סודות.**

## 5. נקודות שדורשות פעולה או אישור ממך

לפי CLAUDE.md, Push ופריסה רק באישורך. לכן הבנייה תתקדם בשלבים:

1. **הפעלת Pages (פעולה שלך, פעם אחת, לפני ה-Push הראשון):** ב-GitHub ← ה-Repository ← Settings ← Pages ← תחת Source לבחור **GitHub Actions**. אדריך צעד אחר צעד. אין עלות (Repository ציבורי).
2. **אישור Push לענף בדיקה ופתיחת Pull Request:** ענף זמני עם כל השינויים. זה מאמת: (א) ה-CI עובר עכשיו, כולל WebKit; (ב) Pull Request **לא** מפרסם (Job הפריסה מסומן Skipped). לאחר מכן Commit זמני עם בדיקה שנכשלת בכוונה באותו PR מאמת שכשל עוצר את הריצה — ואז מוסר.
3. **אישור Merge ל-`main`:** מפעיל את הפריסה הראשונה. אחריה אבדוק את האתר החי (סעיף 7).
4. **אישור Push שני ל-`main`** (שינוי קטן ולא פונקציונלי, למשל סימון 🟡 ב-MILESTONES): יוצר גרסה שנייה לבדיקת עדכון חי.
5. **שאלה פתוחה — בדיקה שכשל ב-`main` לא מחליף את האתר:** בשלב 2 נבדק שכשל עוצר ריצה, אבל ב-PR הפריסה ממילא מדולגת. בדיקה מלאה דורשת Push של Commit שבור ל-`main` ואז Revert (האתר החי אמור להישאר כמו שהוא). אשאל אותך לפני כן; אם לא יינתן אישור — אציג זאת כבדיקה חלקית בדוח.
6. **מחיקת ענף הבדיקה** בסיום — רק באישורך.
7. **בדיקות במכשירים (פעולה שלך):** סעיף 7.2.

- עדכונים: גרסה חדשה נכנסת לתוקף רק אחרי סגירת כל הלשוניות / האפליקציה המותקנת ופתיחה מחדש.

- פקודות פיתוח ובדיקה (קצר).
- טבלת תוצאות בדיקות המכשירים (מערכת הפעלה, דפדפן, תאריך, תוצאה לכל סעיף).

## 7. אימות

### 7.1 אוטומטי, מהמחשב, מול האתר החי (`npm run test:live`)

ב-Chromium עם Service Workers, ובחלק מהבדיקות גם WebKit:

- טעינת `/simon/`: אין תגובות 4xx/5xx, אין שגיאות Console, אין בקשות מחוץ ל-`osnat-fridman.github.io`.
- הגופן, ה-Manifest (`id`/`start_url`/`scope` = `/simon/`) והאייקונים נטענים; ה-Service Worker רשום ב-Scope `/simon/` בלבד.
- מעבר בית ← אודות ← בית.
- אחרי Precache: ניתוק רשת ו-Reload ← הבית והאודות נטענים, משחק קצר נשמר.
- **עדכון שתי גרסאות:** פתיחת הגרסה החיה ותחילת משחק ← (אחרי הפריסה השנייה) בדיקת עדכון ← הגרסה החדשה ממתינה, המשחק ממשיך ו-`data-build` לא השתנה ← סגירת הלשונית ופתיחה מחדש ← `data-build` חדש והתוצאה נשמרה.

בנוסף: הבדיקות הקיימות ב-Chromium וב-WebKit עוברות ב-CI (התנאי ב-DoD).

### 7.2 ידני, במכשירים אמיתיים (פעולה שלך)

אכין רשימה קצרה בעברית לכל מכשיר — iPhone (Safari) ו-Android (Chrome):

1. רישום: דגם, גרסת מערכת ההפעלה, דפדפן.
2. פתיחת הכתובת; השוואה ל-Mockups: לוח עגול, מיקומי צבעים, עברית מימין לשמאל, אין גלילה לצדדים או טקסט חתוך.
3. משחק: התחלה, ארבעה צלילים (לבדוק שמצב שקט כבוי), סיום, ״שחקו שוב״.
4. מעבר לאודות באמצע משחק וחזרה; מעבר לאפליקציה אחרת וחזרה; נעילת מסך וחזרה.
5. התקנה למסך הבית ופתיחה מהאייקון (ללא שורת כתובת).
6. מצב טיסה ← פתיחה מהאייקון ← משחק עם צלילים ← התוצאה מופיעה באודות.
7. דיווח לי: עבד / לא עבד לכל סעיף, וצילום מסך אם משהו נראה לא תקין.

התוצאות ייכנסו לטבלה ב-`README.md`. ליקוי שיימצא — יתוקן במסגרת אבן הדרך הזו לפני סימון 🟡.

## 8. ADRs שיתווספו (צפויים)

- **ADR-15: Workflow אחד עם Job בדיקה ו-Job פריסה, Build יחיד.** כדי שהתוצר שנבדק הוא התוצר שמתפרסם; הרשאות פריסה רק ל-Job הפריסה; Concurrency ללא ביטול ב-`main`.
- **ADR-16: מזהה גרסה מתוך ה-Commit.** `SIMON_BUILD_ID` = SHA מקוצר ב-CI. כל פריסה יוצרת Service Worker חדש באמת, וניתן לזהות את הגרסה החיה.
- **ADR-17: בדיקות מול האתר החי בפרויקט Playwright נפרד** שמופעל ידנית, לא ב-CI (ה-CI רץ לפני הפריסה).
- **ADR-18 (אם יידרש): תיקון הבדיקה ב-WebKit** — לפי הסיבה שתימצא.
