# תוכנית Milestone 2 - משחק מלא ותוצאה אחרונה

מבוסס על: PRD (סעיפים 3–4), ARCHITECTURE (סעיפים 2.1, 3, 4), DESIGN (1.1, 1.2, 2.3) ו-MILESTONES (Milestone 2).
נקודת המוצא: הקוד הקיים מ-Milestone 1 (`index.html`, `src/main.ts`, `src/navigation.ts`, `src/styles.css`, בדיקות ב-`tests/`).

## 1. מה נבנה

- לחיצה על ״התחל״ מתחילה משחק: רצף מצטבר של צבעים אקראיים, עם הארה וצליל לכל צבע.
- תור השחקן: לחיצה על צבע מאירה אותו ומשמיעה את הצליל שלו, ונבדקת מול הרצף.
- 10 שלבים בדיוק. טעות ראשונה = הפסד; השלמת שלב 10 = ניצחון.
- בסיום, בתוך מסך הבית: הודעת הפסד/ניצחון, ניקוד ״X מתוך 10״ וכפתור ״שחקו שוב״.
- שמירת התוצאה האחרונה ב-Local Storage והצגתה בכרטיס שבמסך האודות.
- השהיה בסיסית: מעבר לאודות באמצע משחק עוצר הכול, וחזרה מציגה מחדש את רצף השלב הנוכחי.
- טיפול בתוצאה פגומה/חסרה, בכשל שמירה ובכשל שמע.

**לא נכלל (Milestone 3):** טיפול במעבר לרקע/נעילת מכשיר (Page Visibility, `pagehide`, BFCache) ובדיקות מעברים מקיפות.

## 3. Game Engine

מצב: `phase` (`idle`, `playback`, `input`, `paused`, `won`, `lost`), `sequence`, `inputIndex`, `completedStages`.

פונקציות טהורות (מחזירות State חדש):
- `newGame(rng)` ← רצף של צבע אחד, `completedStages = 0`, `phase = playback`.
- `playbackDone(state)` ← `phase = input`, `inputIndex = 0`.
- `press(state, color)` ← מחזיר `{ state, result }` כאשר `result` הוא:
  - `ignored` — אם `phase !== input` (אין שינוי כלל);
  - `correct` — צבע נכון שאינו האחרון;
  - `stage-complete` — הרצף הושלם וקצר מ-10: `completedStages + 1`;
  - `won` — הושלם רצף באורך 10: `completedStages = 10`, `phase = won`;
  - `lost` — טעות: `phase = lost`, הניקוד נשאר מספר השלבים שהושלמו.
- `nextStage(state, rng)` ← הוספת צבע אחד לסוף הרצף, `phase = playback`.
- `pause(state)` / `resume(state)` — `pause` רק מ-`playback`/`input`; `resume` מחזיר ל-`playback` עם `inputIndex = 0` ואותו רצף.
- `score(state)` = `completedStages`.

הגרלה: `COLORS[Math.floor(rng() * 4)]`; חזרות מותרות.

ערכים קבועים לכל השלבים, בלי האצה:

| קבוע | ערך | משמעות |
| --- | --- | --- |
| `FLASH_MS` | 600 | משך הארת צבע ברצף |
| `GAP_MS` | 250 | הפסקה חשוכה בין צבעים — גם כשאותו צבע חוזר, כך שרואים שתי הארות נפרדות |
| `ROUND_PAUSE_MS` | 800 | הפסקה בין סיום תור השחקן להצגת השלב הבא (וגם לפני הצגה ראשונה) |
| `PRESS_FLASH_MS` | 250 | הארה וצליל כמשוב ללחיצת השחקן |

## 5. שמע (Web Audio)

- AudioContext יחיד, נוצר/מחודש ב-`unlock()` בתוך הלחיצה על ״התחל״, ״שחקו שוב״ ו״חזרה למשחק״.
- צליל מסוג Oscillator (גל `triangle`) עם מעטפת Gain קצרה (התחלה וסיום רכים) למניעת ״קליקים״.
- תדרים קבועים (בהשראת סיימון המקורי): כחול 209Hz, אדום 310Hz, צהוב 252Hz, ירוק 415Hz.
- כשל (אין AudioContext, `resume()` נדחה או נשאר `suspended`) ← המשחק ממשיך עם האורות בלבד ומוצגת הודעה. בלחיצה הבאה ננסה שוב.
- `stopAll()` עוצר מיד צליל שמתנגן (בהשהיה ובסיום).

## 6. Controller, קלט ותצוגה

### זרימה
1. ״התחל״/״שחקו שוב״: `unlock()` ← ביטול כל מה שרץ ← `runToken++` ← `newGame` ← הסתרת אזור הסיום ← המתנת `ROUND_PAUSE_MS` ← הצגת הרצף.
2. סיום הצגה (רק אם `runToken` לא השתנה) ← `playbackDone` ← הפעלת המקטעים ושורת מצב ״תורכם״.
3. לחיצה נכונה ← משוב ונשארים בתור. `stage-complete` ← נטרול קלט ← המתנה ← `nextStage` ← הצגה.
4. `won`/`lost` ← נעילת קלט **לפני** כל דבר אחר ← שמירת התוצאה ← הצגת אזור הסיום.

### מניעת מרוצים
- כל המתנה ו-Callback בודקים שה-`runToken` שלהם עדיין הנוכחי; התחלה חדשה, השהיה וסיום מגדילים אותו ומבטלים את הנגן והשמע.

### קלט
- מסלול אחד: `pointerdown` על המקטעים. מתקבל Pointer פעיל יחיד; נגיעות נוספות בזמן שאצבע לוחצת — מתעלמים מהן עד `pointerup`/`pointercancel`.
- הפעלה במקלדת/טכנולוגיה מסייעת: אירוע `click` עם `detail === 0` עובר לאותה פעולה. `click` שנוצר מ-Pointer — מתעלמים (מונע כפילות).
- המקטעים `disabled` בכל מצב שאינו `input`; בנוסף המנוע מתעלם מקלט כזה (הגנה כפולה).

### השהיה בסיסית (חלק מ-Milestone זה לפי ה-PRD)
- מעבר לאודות כשהמשחק ב-`playback`/`input` ← ביטול נגן ושמע, כיבוי הארות, `pause`.
- ״חזרה למשחק״ ממשחק מושהה ← `unlock()` ← `resume` ← המתנת `ROUND_PAUSE_MS` ← הצגה מחדש של אותו רצף מתחילתו. הקלט החלקי מתאפס, הניקוד נשמר.
- מעבר לאודות לפני משחק או אחרי סיומו — הבית נשאר כפי שהיה.

### תצוגה במסך הבית (החלטת מימוש לבדיקה שלך — לא מופיעה ב-Mockups)
אזור אחד קטן בין הלוח לכפתור, בגובה קבוע כדי שהמסך לא ״יקפוץ״:

| מצב       | מה מוצג                                                                          |
| --------- | -------------------------------------------------------------------------------- |
| המתנה     | ריק; כפתור ״התחל״ (כמו ב-Mockup)                                                 |
| הצגת רצף  | ״שלב N מתוך 10 · צפו ברצף״; ״התחל״ מוסתר                                         |
| תור השחקן | ״שלב N מתוך 10 · תורכם״                                                          |
| הפסד      | ״טעות! המשחק נגמר״, הניקוד ״X מתוך 10״ בגודל בולט, כפתור ״שחקו שוב״ (סגנון משני) |
| ניצחון    | ״כל הכבוד! ניצחתם״, ״10 מתוך 10״, כפתור ״שחקו שוב״                               |

הודעות שגיאה (בטקסט משני, מתחת לאזור):
- כשל שמירה: ״לא ניתן לשמור את התוצאה במכשיר הזה.״
- כשל שמע: ״לא ניתן להשמיע צלילים. אפשר להמשיך לשחק עם האורות.״

מצב Lit: הבהרה חזקה במרכז המקטע והילה (`box-shadow`) בגוון שלו; הצורה, התווית והמיקום לא משתנים.

### מסך אודות
- בטעינה: `loadLastResult()`; קיימת ← ״X מתוך 10״ בגודל בולט; חסרה/פגומה ← ״עדיין אין תוצאה״ (כמו היום).
- בסיום משחק עם שמירה מוצלחת ← הכרטיס מתעדכן מיד.
- בכשל שמירה ← הכרטיס **לא** מציג את התוצאה הישנה כאילו היא החדשה: הוא מציג את התוצאה מהזיכרון (המשחק שזה עתה הסתיים) עם ההערה שלא נשמרה. (לפי ARCHITECTURE 3.2: התוצאה נשארת זמינה בזיכרון.)

## 7. בדיקות

### Vitest
- **מנוע:** רצף התחלתי באורך 1; כל `nextStage` שומר את הקודם ומוסיף צבע אחד; חזרות אפשריות (rng קבוע); אחרי שלב 10 — `won`, אין שלב 11; הפסד בשלב 1 = 0, בשלב 10 = 9, ניצחון = 10; הניקוד עולה רק בהשלמת שלב; `press` מחוץ ל-`input` מחזיר `ignored` בלי שינוי; `resume` מאפס `inputIndex` ולא מוסיף צבע.
- **אחסון:** שמירה וקריאה; JSON פגום, גרסה אחרת, ניקוד מחוץ לטווח או לא שלם ← `null`; `getItem`/`setItem` זורקים ← `null`/`false` בלי קריסה.
- **נגן:** סדר ההארות ומשכיהן; צבע חוזר מופיע כשתי הארות עם הפסקה ביניהן; `cancel()` משחרר את ה-Promise ל-`false` ולא מדליק יותר.
- **Controller (עם DOM של jsdom/happy-dom ו-Fake Timers):** קלט ב-Playback ואחרי סיום לא משנה דבר; תוצאה נכתבת פעם אחת בסיום בלבד; התחלה חדשה באמצע משחק לא כותבת תוצאה; השהיה וחזרה מציגות אותו רצף; Callback ממשחק קודם לא משנה State.
  - תלות פיתוח חדשה: `happy-dom` (סביבת DOM לבדיקות Vitest). תעודכן ב-Lockfile.

### Playwright (מול Build, Chromium + WebKit)
- הרצת זמן מואצת באמצעות `page.clock` של Playwright, כדי שמשחק מלא לא יימשך דקה.
- הרצף נקרא מתוך הדף בלי ״דלת אחורית״ במוצר: הבדיקה מאזינה להופעת `.pad--lit` בזמן ההצגה ולוחצת בהתאם.
- תרחישים: משחק עד ניצחון (10 מתוך 10); הפסד מכוון ובדיקת הניקוד; ״שחקו שוב״ מתחיל משלב 1; מעבר לאודות מציג את התוצאה; Reload — התוצאה נשארת והבית במצב המתנה; Reload באמצע משחק לא דורס תוצאה; מעבר לאודות באמצע משחק וחזרה — אותו רצף מוצג מחדש; תוצאה פגומה ב-Local Storage ← ״עדיין אין תוצאה״; `setItem` חסום ← הודעת כשל שמירה; ללא AudioContext ← הודעת כשל שמע והמשחק ממשיך.
- בדיקת חזותית ידנית שלי (צילומי מסך במובייל) למצבי התור והסיום.

### CI
ללא שינוי ב-Workflow: הוא כבר מריץ typecheck, Vitest, Build ו-Playwright.
